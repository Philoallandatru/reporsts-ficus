## 1. 权重驻留：按热度排补集，并协调两级淘汰

## 2. 读盘：批内合并、更多在途请求、以及是否保留 mmap

**Strata 文件层。** `FileExpertSource` 支持 mmap、显式无缓冲读等分支。Windows 直读把每个专家的 gate/up/down 从对应分片换算成 4 KiB 对齐窗口，先按文件和偏移排序，合并同文件且间隙不超过 1 MiB 的窗口，合并跨度不超过 32 MiB。批内先把读提交，再逐个等待完成，随后只复制所需角色字节。1 MiB 间隙和 32 MiB 单请求上限是该版本 Windows 分支常量，不是所有平台的统一设置；合并可能多读间隙，吞吐要连同实际读放大验证。线程本地 scratch 随批次需求增长，不能直接拿它替换 P6 的硬 staging 预算。源码：[打开 direct 句柄](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:2465)、[对齐、排序、合并](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:2752)、[scratch、批量提交与完成](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:2828)。

## 3. Decode：GPU、CPU、PCIe 分工，以及每层同步

**Strata。** verifier 在 GPU 图内计算路由，通过映射内存的 doorbell 交出 ID、权重与激活。host 把同层窗口的专家去重分组：GPU slot 命中直接组内计算；部分 miss 如果已有 pinned RAM 副本，可通过 PCIe lane 搬到 staging 或经映射地址访问，由 GPU 算；其余 miss 从 RAM/文件取得 blob，交给 CPU 专家池。发布 GPU 计划并启动 PCIe lane 之后，CPU 池才计算自己的份额；在图内等待各自完成并合并专家结果。仍有同步，只是同步边界和能重叠的工作不同。Q5 历史日志记录 15 个 CPU worker、PCIe 配比和路由计数，不能把 CPU lane 算成“每个 miss 都上传”，也不能称为 SSD 到 VRAM 直连。源码：[VRAM/PCIe 分流](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:5041)、[先发布 GPU 计划](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:5140)、[CPU pool 计算](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:5370)；[门铃发布](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/verify.cpp:2257)、[分组计算与等待 CPU](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/verify.cpp:2397)；[实测 PCIe 配比和日志分母](C:/Users/Administrator/Documents/Code/tasks/strata-lab/runs/outofcore-5080-budget24-01/engine.log:83)。

## 4. Prefill 与 PLE：两个额外的数据流

## 5. MTP、路由尾跳与质量契约

MTP 会对上一个输出及候选后续 token 一次运行多行主模型验证，接受匹配前缀再提交状态；接受时可以少跑串行窗口，同一个专家也可能服务同窗多行，拒绝时仍有已经做掉的计算。它的效果取决于草稿、接受率和每窗成本。Strata 的 route tail skip 则明确改变计算：同一窗口里某 expert 每次被选都在指定尾部名次，而且 GPU 未命中时，可跳过这个 expert，其行贡献置零，其他路由权重不重归一化。因此等输出长度、同 GGUF、甚至主模型 top-k 参数相同，都不足以把开启尾跳的结果当作同计算工作量。源码：[选择、接受和固定 continuation](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/program/generate.cpp:19161)、[提交已接受状态](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/program/generate.cpp:19202)、[每窗推进方式](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/program/generate.cpp:20355)；[尾跳判定](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:4963)、[尾跳直接置零](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:5261)。

## 6. 资源、计数与优先级

- **分清硬预算的作用域。** P6 专家 RAM 含 payload、槽与尺寸组元数据，staging / PLE / GPU 工作区另计；Strata `--resident-budget-gib` 限专家副本，受机器当时的可用 RAM/commit 夹紧；原生 mmap 交给 OS 文件页缓存。即使给三者同一进程工作集上限，OS standby 仍可在进程之外保留映射页，RSS 与 private commit 也不是一个量。内核显存、固定权重、KV 和图缓冲应另列整卡实测。见 [P6 记账字段](C:/Users/Administrator/Documents/Code/my-code/lm-llama/llama.cpp/src/llama-expert-store.cpp:327)、[Strata 副本预算](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:3583)、[映射缺页与工作集边界](C:/Users/Administrator/Documents/Code/my-code/lm-llama/research/ooc-p5-20261110/RESULTS.zh-CN.md:135)。
- **盘读不要混口径。** P6 逻辑字节是需要的有效权重，aligned bytes 是 direct 调用返回的字节；Strata 源码在某些返回 mmap 地址分支也累计 file-read bytes；原生进程 `IO_COUNTERS` 则可能漏掉 mmap 缺页。跨引擎采用同一 decode 时间窗内的物理 DiskIO 按模型路径/PID 统计，并保留整盘背景/归属差。若只有整盘计数，标作整盘流量而不是独占 I/O。ETW 检查事件丢失及窗口完整覆盖，循环日志报告“零丢失”也可能覆盖了头部。见 [P6 完成统计](C:/Users/Administrator/Documents/Code/my-code/lm-llama/llama.cpp/src/llama-expert-store.cpp:475)、[Strata blob 来源选择与计数](C:/Users/Administrator/Documents/Code/tasks/strata-lab/Strata-8a42a9457db62568d1663c8c1bcc01cfffae5355/src/core/expert_source.cpp:4663)、[曾发生的 ETW 保留窗口限制](C:/Users/Administrator/Documents/Code/my-code/lm-llama/research/ooc-p6-20261110/DIAGNOSIS.md:28)。
- **优先做两个独立消融。** 一是同分片、同 offset/字节、同 I/O 队深，对照持有和关闭 mmap/缓冲句柄，测提交到完成延迟与真实在途深度；可用 Strata `STRATA_KEEP_MAPPING=1` 作为另一个引擎内的隔离变量，记录剩余映射与是否实际关闭。P6 的 tensor/ggml buffer 还引用视图，直接 unmap 有悬空风险，生产修改须先把权重身份及文件偏移与可读 host 指针解耦、验证所有图调用方。二是用同路线 trace 估算互补驻留与热启动会减少多少冷字节；运行时必须协调 GPU 换出和 RAM 保留，计入交换、初始化和热度污染成本。二者分别测，一次只改一项。
- **再扩大流水线。** 已知队列能并行时，再在固定 staging 预算下加同文件合并、有限并发和有界 scatter，跟踪逻辑、对齐、物理三套字节及 P50/P99。保持 read/transfer/consume 租约、错误排空和逐位输出。缩短 host/GPU 同步与让 RAM 专家走 CPU 可在文件供给问题清楚后另做；需要新生命周期、混合算术和后端可移植性验证。MTP 是独立性能实验，尾跳是另一个质量档位。TTFT 优化则先用实际长提示测分块与借槽，不重复实现 P4 已有的一般 prefill 准入绕过。
