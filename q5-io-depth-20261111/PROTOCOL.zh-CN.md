# P6 冷权重读队列深度实验

2026-11-11。后续于 [Q5 三方对照](../q5-strata-compare-20261111/REPORT.zh-CN.md)：同工作量下，P6 和 Strata 的典型物理读大小相同，但 Strata 正常轮的磁盘在途数更高；Strata 自身也曾出现慢段。问题是提高 P6 的在途槽是否能带来实际收益。实验不以解决 SSD 秒级慢读或复现历史 Strata 开 MTP 的速度为验收。

候选仅把专家路径允许的在途槽上限由 2 提到 8，FIFO 的读、填缓存、上传、等待和取消排空顺序保持不变。`LLAMA_EXPERT_IO_DEPTH` 仍默认 2；PLE 仍为 2。固定 staging 32 MiB，深度 8 时每槽约 4 MiB，能容纳当前 Q5 的最大专家角色及对齐空隙；核对读次数、逻辑和对齐字节是否变化。槽控制结构增加的字节单列。源文件和重链接都在独立目录，生产源码、共享构建、冻结 P6 二进制不修改。

复用三方对照的 Q5 六分片、128 个提示 token 与 128 个强制输出 token，同一 5080、4 GiB GPU 专家缓存、16 GiB RAM 专家缓存、64 MiB PLE RAM、24 GiB 硬工作集、固定上下文和微批。无 MTP、专家跳过或合并读取。每个新进程只跑一条请求；自然 OS 缓存状态，一次只运行一个实验模型。不改页文件、全局缓存和其他进程。应用完整 logits 暂存到约 121 MiB 的公共测量缓冲，退出前、ETW 停止后写文件；计时包含暂存 memcpy。各臂探针相同，和旧三方的数字只做背景对照。

先跑冻结 DLL 深度 2 一次作为身份和正确性对照，随后候选两轮，每轮包含四种深度，顺序互为反向：`2,4,1,8` 和 `8,1,4,2`。保留慢轮和失败。合格样本必须同一轨迹、与冻结版全量 float32 位模式一致、预算与租约无超限、ETW 覆盖完整且无丢失。分析首末可见 token 的 127 个间隔、TTFT、p50/p95/p99，物理 Q5 分片读 MiB/步与 GiB/s、单笔完成时间及 `QD/I` 分布，另报告应用 session 的读取与上传等待。ETW 设备在途数不等于应用槽数；应用等待不等于设备服务时间。

预设筛选：深度 4/8 至少在两轮都比同轮候选深度 2 快，吞吐中位数至少高 10%，每轮 token p99 相对同轮深度 2 不增加超过 10%，物理/逻辑/对齐读取工作量放大不超过 1%。通过才建议做长提示与长输出的追加验证；未通过保持 P6 深度 2，区分「队列根本没加深」「加深但没有端到端收益」和「受慢段干扰，证据不足」。两轮只是筛选，不能作为长期默认值的依据。

大产物：`D:/q5-io-depth-20261111`，包括重链接命令、生成源码、二进制、每轮 ETW 和 logits。工作区保留构建身份、只改深度的 patch、单测日志和最终汇总。

采集偏差记录：原 `r2-d1` 发出完整的 128 个 token 和 `GREEDY_MATCH 128`，但逐步读盘期间 ETW 顺序文件达到 1,536 MiB 上限，停止时返回 `0x1069`，探针未写出 logits。该次保留为仅有计时的异常样本，不参与正式物理读统计。第二轮其余两臂保持顺序，结束后以 `r2-d1-retry` 补采；从 `r2-d4` 起只把 ETW 文件上限改为 3,072 MiB。事件、缓冲设置、筛选阈值和模型参数不变。不能用补采覆盖慢轮，也不能用原慢轮宣称深度 1 的常态吞吐。
