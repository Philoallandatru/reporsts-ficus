## 2. Patent Search Entry Points and Classification Notes

| Area | Conclusion | URL | Why usable | Limitations |
| --- | --- | --- | --- | --- |
| Search tool | Use Google Patents Advanced Search for quick discovery, assignee filtering, CPC filtering, family links, citations, and machine translations. | https://www.google.com/advanced_patent_search | Google Patents is explicitly designed for searching and reading patent full text and prior art, and it is practical for broad SSD/FTL/LDPC query exploration. | It is not the legal system of record; verify prosecution/file-wrapper state through USPTO Patent Center or relevant patent office when legal status matters. |
| Search tool | Use USPTO Patent Public Search as the authoritative U.S. search portal for U.S. patents and published applications. | https://www.uspto.gov/patents/search/patent-public-search | USPTO describes it as public access to U.S. patents and published applications, including basic and advanced search. | It is U.S.-centric; for CN/EP/WO family members use Google Patents family links or official regional patent offices. |
| Search tool | Use USPTO Patent Center for application lookup by application number, patent number, PCT number, or publication number. | https://patentcenter.uspto.gov/search | It is the official route for U.S. application status and document lookup after a candidate patent is identified. | It is less convenient for broad keyword discovery than Google Patents; use it for confirmation, not first-pass mining. |
| CPC taxonomy | Use CPC as the main classification vocabulary; USPTO and EPO jointly manage CPC, and the official CPC table should be checked for current releases. | https://www.cooperativepatentclassification.org/cpcSchemeAndDefinitions/table | It is the official CPC publication entry and is suitable for keeping the knowledge-base classification terms current. | CPC symbols are frequently revised; record CPC version/date during intake and expect reclassification notes. |
| SSD/controller | Start SSD controller, firmware, storage interface, FTL, GC, wear-leveling, namespace, stream, and placement searches under G06F 3/06. | https://www.uspto.gov/web/patents/classification/cpc/html/cpc-G06F.html | USPTO's CPC scheme defines G06F 3/06 as digital input/output to record carriers, including RAID, emulated record carriers, and networked record carriers. | G06F is broad; use keywords such as "solid state drive", "flash translation layer", "garbage collection", "wear leveling", "write amplification", "namespace", "stream", "FDP", and assignee filters. |
| SSD memory management | Use G06F 12/00 as a secondary class for memory addressing/allocation aspects that may overlap FTL mapping, cache, and placement. | https://www.uspto.gov/web/patents/classification/cpc/html/cpc-G06F.html | USPTO's G06F scheme lists G06F 12/00 for accessing, addressing, or allocating within memory systems or architectures. | G06F 12/00 is not SSD-specific; pair it with "NAND", "SSD", "FTL", or "non-volatile memory" to reduce irrelevant memory-management results. |
| Error correction | Use G06F 11/00 and G06F 11/07/11/08 branches for computing-system error detection/correction and monitoring around SSD controllers. | https://www.uspto.gov/web/patents/classification/cpc/html/cpc-G06F.html | USPTO's G06F scheme identifies G06F 11/00 as error detection, error correction, and monitoring, with references to static-store and record-carrier classes. | LDPC code construction itself often belongs in H03M 13, while NAND device test/repair may belong in G11C 29/00; use cross-class queries. |
| NAND device physics/circuits | Use G11C 16/00 for erasable programmable read-only memory, especially NAND program/read/erase, disturb, sensing, threshold, retention, and wearout mechanisms. | https://www.uspto.gov/web/patents/classification/cpc/html/cpc-G11C.html | USPTO's G11C scheme explicitly covers EPROM/EEPROM style nonvolatile memories and subgroups for variable threshold cells, series cells, sensing, power, disturbance, retention, and wearout. | It captures memory-device internals more than SSD firmware policy; combine with G06F 3/06 for controller/FTL inventions. |
| NAND device structure | Use H10B as a cross-check for individual electronic memory device structures, especially 3D NAND core/periphery/staircase concepts. | https://www.uspto.gov/web/patents/classification/cpc/html/defH10B.html | USPTO's H10B definition discusses semiconductor/solid-state memory devices and explicitly uses NAND strings, core region, peripheral region, and 3D NAND staircase structures in its terminology. | H10B is device-structure heavy; it will miss many firmware, host interface, and system-level SSD patents. |
| LDPC/ECC | Use H03M 13 for LDPC, BCH, Reed-Solomon, iterative decoding, soft decoding, rate-compatible LDPC, and implementation complexity searches. | https://www.uspto.gov/web/patents/classification/cpc/html/cpc-H03M.html | USPTO's H03M scheme includes LDPC-specific branches such as QC-LDPC, LDPC convolutional codes, iterative decoding, and rate-compatible LDPC. | H03M is not storage-specific; combine with "NAND", "flash memory", "SSD controller", "read retry", "soft bit", "LLR", and "decoder latency". |
| FTL examples | Use this Google Patents result as a seed patent for FTL, block compaction, dynamic wear leveling, static wear leveling, and logical-to-physical remapping terminology. | https://patents.google.com/patent/US20120317377A1/en | The patent text explicitly discusses FTL behavior, block compaction, garbage collection, dynamic wear leveling, static wear leveling, and remapping. | A single patent is not a complete FTL taxonomy; use it to harvest keywords, assignees, CPC symbols, backward citations, and family links. |
| PLP examples | Use this Google Patents result as a seed patent for SSD power loss protection, backup power sources, supercapacitors, and volatile-buffer flush behavior. | https://patents.google.com/patent/US20170185335A1/en | The patent description explicitly frames power loss protection for SSDs and describes backup power source context. | Patent claims may focus on a specific mechanism; do not generalize it into all PLP designs without more families and product documentation. |
| SLC cache examples | Use this Google Patents result as a seed patent for SLC/MLC/TLC cache management and mixed-level nonvolatile memory. | https://patents.google.com/patent/US20220129168A1/en | The patent text explicitly covers SLC memory cells serving as a high-speed cache for MLC-style capacity tradeoffs. | Terminology varies: search "pseudo-SLC", "pSLC", "SLC cache", "hybrid cache", "folding", and "direct-to-TLC/QLC" to avoid missing families. |
| LDPC examples | Use this Google Patents result as a seed patent for LDPC capability adjustment, error statistics, and storage-device LDPC monitoring. | https://patents.google.com/patent/US8413029B2/en | The text explicitly discusses LDPC decoding, corrected error statistics, and storage-device error-rate observations. | It is only one LDPC-storage example; extend with H03M 13 CPC search and keywords "soft decoding", "LLR", "read threshold", "read retry", and "NAND". |
| Placement/FDP examples | Use this Google Patents result as a seed patent for FDP-like reclaim-unit data placement and host-controlled placement concepts. | https://patents.google.com/patent/US12405729B2/en | The patent text explicitly references flexible data placement, reclaim units, handles, and device-level garbage collection influence. | FDP is also a standards feature; patent search should be separated from NVMe specification intake to avoid mixing normative protocol behavior with claimed implementations. |
| FDP standards context | Use the NVMe FDP official blog as a non-patent intake pointer for placement terminology such as write amplification, placement hints, and FDP. | https://nvmexpress.org/nvmeflexible-data-placement-fdp-blog/ | It is published by NVM Express and frames the standards motivation for FDP, making it useful for choosing patent search terms. | It is not the full NVMe specification; formal fields, commands, and conformance rules require official NVMe specification intake. |

## 3. Reusable Patent Query Starters

| Topic | Conclusion | URL | Why usable | Limitations |
| --- | --- | --- | --- | --- |
| FTL / garbage collection / wear leveling | Start with a broad Google Patents query combining "flash translation layer", SSD, garbage collection, and wear leveling. | https://patents.google.com/?q=%22flash+translation+layer%22+SSD+%22garbage+collection%22+%22wear+leveling%22 | This query targets the most common controller-firmware vocabulary and should surface FTL mapping, GC, compaction, and wear leveling patents. | It can overfit to documents that use the exact term "FTL"; repeat with "logical to physical", "mapping table", "valid page", and "block compaction". |
| PLP / power fail | Start with "solid state drive" plus "power loss protection" and capacitor/flush terms. | https://patents.google.com/?q=%22solid+state+drive%22+%22power+loss+protection%22+capacitor+flush | This query directly targets SSD PLP implementations that combine hardware energy reserve and firmware flush/shutdown behavior. | Some vendors use "sudden power off recovery", "SPOR", "power fail", "backup power", or "data protection"; run variants. |
| LDPC / soft decoding | Start with NAND plus LDPC plus soft decoding/read-retry terms. | https://patents.google.com/?q=NAND+LDPC+%22soft+decoding%22+%22read+retry%22 | This query targets the intersection of NAND reliability, ECC, and controller read-recovery pipelines. | It may retrieve communication-code patents unless constrained with NAND, flash memory, SSD controller, or G06F/G11C classes. |
| SLC cache / pSLC | Start with SLC cache plus TLC/QLC and pseudo-SLC synonyms. | https://patents.google.com/?q=%22SLC+cache%22+SSD+TLC+QLC+%22pseudo-SLC%22 | This query targets controller policies that trade capacity for write performance by programming multi-bit cells in SLC mode. | Many patents avoid the phrase "SLC cache"; repeat with "single level mode", "folding", "hybrid cache", and "multi-level memory". |
| Placement / FDP / streams | Start with flexible data placement, reclaim unit, write stream, and placement identifier terms. | https://patents.google.com/?q=%22flexible+data+placement%22+SSD+%22reclaim+unit%22+%22placement+identifier%22 | This query targets modern host-directed placement and FDP-like interfaces that interact with internal GC and write amplification. | Older inventions may use "write stream", "data temperature", "hot/cold data", or "host hint" rather than FDP terminology. |
| NAND device / disturb / retention | Start with NAND flash plus threshold voltage, disturb, retention, and read-retry terms. | https://patents.google.com/?q=%22NAND+flash%22+%22threshold+voltage%22+disturb+retention+%22read+retry%22 | This query targets the lower-level device behavior that controller firmware must compensate for. | It can retrieve die/circuit patents rather than SSD patents; combine G11C/H10B with G06F when controller implications matter. |
