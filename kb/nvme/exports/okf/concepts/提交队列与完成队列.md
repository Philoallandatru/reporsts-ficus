# 提交队列与完成队列

## 概述

提交队列（Submission Queue，SQ）和完成队列（Completion Queue，CQ）是 NVMe 协议中主机与控制器之间进行命令通信的核心机制。控制器作为主机进入 NVM 子系统的"服务窗口"，从提交队列中取命令，协调数据访问，再将结果放入完成队列；主机不会直接操作底层闪存。^[nvme-controller.md:3]

## 工作原理

### 提交队列

提交队列用于存放主机准备发送给控制器的命令。当应用程序发起 I/O 请求时，NVMe 驱动将命令封装后放入提交队列，并通知控制器有新命令待处理。

### 完成队列

完成队列用于存放控制器的处理结果。当控制器执行完命令后，会将完成状态写入完成队列，驱动通过检查完成队列获取命令执行结果。

## 命令处理流程

典型的命令处理流程如下：

```text
主机应用 --> 驱动 --> 提交队列 --> 控制器 --> [[命名空间|命名空间]]/存储资源
                                  |
                                  +--> 完成队列 --> 驱动 --> 应用
```

1. 主机应用发出 I/O 请求
2. NVMe 驱动将命令写入提交队列
3. 控制器从提交队列取出命令并执行
4. 控制器将执行结果写入完成队列
5. 驱动读取完成队列，通知应用程序

^[nvme-controller.md:5-11]

控制器负责命令处理和队列协作，而[命名空间](/concepts/命名空间.md)才是主机读写的逻辑存储对象。^[nvme-controller.md:13]

## 命令标识与匹配

NVMe 协议通过**命令标识符（Command ID）** 来关联请求与响应。驱动将命令写入提交队列时，会为每个命令分配唯一的 ID；控制器完成执行后，在完成队列条目中包含该 ID，使得驱动能够准确地将完成通知匹配到原始请求。^[nvme-controller.md:15-19]

例如，数据库发出一次写入操作：NVMe 驱动将命令放入提交队列并通知控制器；控制器执行后写入完成队列；驱动通过命令 ID 找到原请求，再通知数据库"写入已完成"。^[nvme-controller.md:15-19]

## 队列管理的重要性

"控制器很快"不仅指介质速度快，还要求控制器能够正确管理并行队列、命令状态和完成通知。在高并发场景下，队列的效率直接影响整体性能。^[nvme-controller.md:15-19]
