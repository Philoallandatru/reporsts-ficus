# 命名空间（Namespace）

命名空间是 NVMe 子系统中主机实际进行数据读写操作的逻辑存储对象。控制器负责命令处理和队列协作，而命名空间才是承载用户数据的实体。^[nvme-controller.md:8-13]

## 基本概念

在 NVMe 架构中，主机应用的数据操作最终指向特定的命名空间。控制器作为"服务窗口"接收来自主机的命令，但这些命令读写的数据实际存储在命名空间所对应的底层存储资源上。^[nvme-controller.md:3, 13]

## 数据读写流程

一次典型的 I/O 操作流程如下：

```
主机应用 --> 驱动 --> 提交队列 --> 控制器 --> 命名空间/存储资源
                                  |
                                  +--> 完成队列 --> 驱动 --> 应用
```

数据库发出写入请求时，NVMe 驱动将命令放入提交队列并通知控制器；控制器执行后将结果写入完成队列。驱动通过命令 ID 找到原请求，最终通知应用"写入已完成"。^[nvme-controller.md:7-11, nvme-controller.md:15-19]

## 与控制器的关系

- **控制器**：负责命令处理、队列协作和完成通知，不直接操作底层闪存
- **命名空间**：提供逻辑存储视图，是主机读写的目标对象

一个 NVMe 子系统可以包含一个或多个命名空间，控制器通过 Identify [Controller](/concepts/controller.md) 数据结构报告其类型和功能。^[nvme-controller.md:25-29]

## 控制器类型与命名空间

不同类型的控制器与命名空间的交互能力不同：

| [控制器类型](/concepts/控制器类型.md) | 能否访问命名空间 | 能否处理用户 I/O |
|---|---|---|
| I/O 控制器 | 可以 | 可以 |
| [发现控制器](/concepts/发现控制器.md) | 不可以 | 不可以 |
| 管理控制器 | 可以（管理用） | 不可以 |

管理控制器可以管理命名空间、虚拟化、健康状态或子系统操作，但通常不直接承担用户数据 I/O。^[nvme-controller.md:25-29, nvme-controller.md:59-62]

## 相关概念

- 控制器 — 主机进入 NVM 子系统的"服务窗口"
- 提交队列 — 主机向控制器提交命令的队列
- 完成队列 — 控制器向主机返回处理结果的队列
- I/O 控制器 — 可以直接访问命名空间的控制器类型
