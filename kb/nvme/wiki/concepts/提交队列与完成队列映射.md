# 提交队列与完成队列映射

提交队列（Submission Queue，SQ）与完成队列（Completion Queue，CQ）之间的映射关系是 NVMe 协议的核心设计之一，它决定了命令提交与完成通知之间的关联方式。映射规则因传输模型的不同而存在显著差异。^[nvme-queue-pair.md:3, nvme-queue-pair.md:24-35]

## 基本概念

队列对由两部分组成：主机用于提交命令的**提交队列**和控制器用于发布完成通知的**完成队列**。管理队列承载管理和控制操作；I/O 队列承载 I/O 命令集的命令。^[nvme-queue-pair.md:3]

可以将这个过程类比为取号与叫号系统：主机把待办事项放进提交队列，如同顾客取号后把业务单交到窗口；控制器处理完后把结果写进完成队列，如同屏幕叫号并给出办理结果。每一条完成记录都带有足够的标识，驱动可以对应回原来的请求。^[nvme-queue-pair.md:9]

## 基于内存传输的映射（PCIe）

对于基于内存的传输模型（如 PCIe），队列直接驻留在主机内存中，映射规则具有更大的灵活性。^[nvme-queue-pair.md:26-29]

**关键特点：**

- **多对一映射**：多个 I/O 提交队列可以共享一个 I/O 完成队列。这意味着多个 CPU 核心或线程可以向各自的提交队列提交命令，而共享同一个完成队列来接收完成通知。^[nvme-queue-pair.md:28]
- **管理队列严格一对一**：管理队列对采用严格的[[队列对]]一对一映射，不支持多对一配置。^[nvme-queue-pair.md:29]

```
基于内存的 I/O 映射示意：
提交队列 A ──┐
             ├──→ 完成队列 X
提交队列 B ──┘
```

## 基于消息传输的映射（NVMe over Fabrics）

对于 [[nvme-over-fabrics|NVMe over Fabrics]] 环境，映射规则更为严格。^[nvme-queue-pair.md:31-33]

**关键特点：**

- **一对一映射**：每个 I/O 提交队列必须与一个 I/O 完成队列一对一映射，不支持多对一的 I/O 队列映射。^[nvme-queue-pair.md:32-33]
- **无完成队列流量控制**：基于消息的模型不使用内存门铃机制，流量控制由传输层的胶囊投递和容量预留驱动。^[nvme-queue-pair.md:55]

```
[[nvme-over-fabrics|NVMe over Fabrics]] I/O 映射示意：
提交队列 A ────→ 完成队列 A
提交队列 B ────→ 完成队列 B
（不支持多对一映射）
```

## 管理队列的特殊性

管理队列使用标识符 `0` 的提交队列和完成队列。管理提交队列与其完成队列是唯一关联的，这是协议中唯一强制一对一映射的队列对类型。^[nvme-queue-pair.md:45]

管理队列具有以下特性：

- 管理队列不能通过创建/删除 I/O 队列的管理命令删除
- 管理完成队列的中断从不进行合并
- 基于消息的管理提交队列还受发现日志页条目 `ASQSZ` 限制 ^[nvme-queue-pair.md:96]

## 完成关联机制

无论采用何种传输模型或映射方式，完成通知与原始请求之间的关联都依赖于相同的标识机制。^[nvme-queue-pair.md:56-69]

**关联方式：**
完成队列条目包含**提交队列标识符（SQID）**和**命令标识符（Command ID）**。主机通过这两个字段将完成通知与原始命令对应。^[nvme-queue-pair.md:69]

**无序完成的特点：**

- 控制器可以按任意顺序处理同一提交队列或跨提交队列的命令（融合操作除外）
- 完成通知也是无序的
- 数据库等应用必须以完成记录中的提交队列 ID 与命令 ID，而非提交顺序，识别结果 ^[nvme-queue-pair.md:11]

**阶段标签（Phase Tag）：**
在基于内存的模型中，变化的阶段标签标识新发布的完成队列条目，支持主机无需读取寄存器即可检测新条目。^[nvme-queue-pair.md:113]

## 映射与队列生命周期的关系

队列映射规则与队列的创建和删除顺序紧密相关。^[nvme-queue-pair.md:100-115]

### 创建顺序

对于基于内存的传输，正确的创建顺序为：

1. 配置管理队列
2. 协商队列数量（使用特性标识符 `07h`）
3. 创建完成队列
4. 创建关联的提交队列

**关键约束：**

- 完成队列必须先于其关联的提交队列创建
- 完成队列必须比提交队列存活更长
- 在任何 I/O 队列已存在后调用设置操作会导致"命令序列错误" ^[nvme-queue-pair.md:83]

### 删除顺序

```
配置管理队列 → 协商队列数量 → 创建完成队列 → 创建提交队列
                               删除完成队列 ← 删除每条关联的提交队列
```

### 共享完成队列的处理

对于基于内存的共享完成队列，每条关联的提交队列应该在完成队列之前删除，并在完成队列之后重建。主机应先让受影响队列静止，因为删除会中止待处理命令。^[nvme-queue-pair.md:260-261]

## 传输模型对比

| 特性 | 基于内存的模型 | 基于消息的模型 |
|---|---|---|
| **命令提交** | 写入尾部门铃寄存器 | 向提交队列添加胶囊 |
| **完成关联** | SQID + 命令ID + 阶段标签翻转 | SQID + 命令ID（阶段标签不适用） |
| **I/O 映射** | 多对一允许 | 必须一对一 |
| **流量控制** | 尾部/头部门铃寄存器 | 胶囊投递和容量预留 |
