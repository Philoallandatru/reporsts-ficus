# 基于消息的传输

## 概述

基于消息的传输（Message-Based Transport）是 NVMe 规范定义的两种基本通信模型之一。在这种模型中，主机和控制器通过网络结构（Fabric）交换封装的消息，命令和响应被打包成**胶囊**（Capsule），通过网络协议传递。^[nvme-transport-models.md:27-31]

这种传输模型的典型代表是 **NVMe over Fabrics**，包括基于 TCP、RDMA 等网络协议的实现。^[nvme-transport-models.md:28-31]

## 传输架构

NVMe 采用分层架构，将传输无关的核心协议与具体传输实现分离：

```
┌─────────────────────────────────────────────────────┐
│  NVMe 核心架构                                       │
│  (队列机制、命令集、控制器属性等)                    │
└─────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────┐
│  传输绑定层 (Transport Binding)                      │
│  (传输特定的适配和服务)                              │
└─────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────┐
│  NVMe 传输层 (NVMe Transport)                        │
└─────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────┐
│  底层网络协议 / 物理网络结构                         │
│  (不属于 NVMe 规范范围)                              │
└─────────────────────────────────────────────────────┘
```

这种分层设计确保传输无关的 NVMe 接口位于绑定层之上、原生网络结构（Fabric）之下。^[nvme-transport-models.md:79]

## 两种子类型

基于消息的传输可进一步细分为两种子类型，区分标准是传输过程中是否有显式内存操作参与：^[nvme-transport-models.md:42-44]

| 子类型 | 命令/响应传递 | 数据传输方式 |
|--------|--------------|-------------|
| **纯消息模式**（Message-Only） | 胶囊/消息 | 仅通过胶囊/消息 |
| **消息/内存混合模式**（Message/Memory） | 胶囊 | 胶囊或显式内存操作 |

两种子类型共享基于胶囊的命令和响应传输方式，区别在于数据如何移动。^[nvme-transport-models.md:133]

## [[胶囊机制|胶囊机制]]

### 胶囊的定义

在 [[nvme-over-fabrics|NVMe over Fabrics]] 中，胶囊（Capsule）是信息交换的基本单位，可以包含：^[nvme-transport-models.md:95-103]

- 一条命令或一个响应
- 可选的命令/响应数据
- 散布/聚集列表（SGL，Scatter-Gather List）

### 命令胶囊结构

命令胶囊从主机发往控制器，结构如下：^[nvme-transport-models.md:159-167]

```
字节 0                 63 64                              N-1
┌────────────────────────┬──────────────────────────────┐
│  64 字节 SQE           │  数据 或 额外的 SGL           │
│  (提交队列条目)        │                               │
└────────────────────────┴──────────────────────────────┘
```

### 响应胶囊结构

响应胶囊从子系统返回主机，结构如下：^[nvme-transport-models.md:169-178]

```
字节 0         15 16                                     N-1
┌──────────────────┬────────────────────────────────────┐
│  16 字节 CQE     │  可选数据                           │
│  (完成队列条目)  │                                     │
└──────────────────┴────────────────────────────────────┘
```

**关键要点：** 命令胶囊在 SQE 之后**不会同时混合**数据和额外的 SGL。响应 CQE 与之前的某个命令胶囊一一对应。^[nvme-transport-models.md:180-183]

## 数据放置策略

通过 SGL（Scatter-Gather List）支持多种数据放置策略：^[nvme-transport-models.md:187-194]

| SGL 选择的数据放置方式 | 胶囊处理结果 |
|---------------------|-------------|
| **内存地址** | 数据通过传输支持的内存事务传输（如 RDMA） |
| **偏移量** | 数据直接承载在命令或响应胶囊中 |
| **额外描述符段** | 描述符紧接 SQE 之后连续排列 |

对于胶囊内数据，从字节 64 开始放置额外的胶囊内 SGL，命令数据从字节偏移量 `64 + ICDOFF × 16` 开始。^[nvme-transport-models.md:197-200]

## 传输层与端口

### NVMe 传输层的职责

NVMe 传输层在底层网络结构之上提供以下服务：^[nvme-transport-models.md:110-112]

- **可靠交付**：确保命令和数据正确传递
- **传输无关性**：与底层物理互联和协议无关

### [[nvm-子系统端口|NVM 子系统端口]]

NVM 子系统端口是具有以下特性的协议接口：^[nvme-transport-models.md:115-121]

- 可以聚合一个或多个物理网络接口
- 通过 **NQN**（NVMe Qualified Name）和 **16 位端口 ID** 进行标识
- 一个端口可以支持多种传输协议
- 已连接的控制器会绑定到特定的子系统端口

## 胶囊大小

- **管理队列胶囊大小**：由传输绑定固定
- **I/O 队列胶囊大小**：通过 Identify [[controller|Controller]] 命令报告，包括 I/O 命令胶囊和 I/O 响应胶囊的大小

管理队列和 I/O 队列均支持基于 SGL 的传输，传输绑定定义了哪些 SGL 类型可以选择：胶囊内数据或显式内存事务。^[nvme-transport-models.md:139-151]

## 错误处理

描述符的数量和空间限制来自 Identify Controller：^[nvme-transport-models.md:203-208]

- 违反描述符数量限制：命令会被中止，返回 **Invalid Number of SGL Descriptors** 错误
- SGL 偏移量无效：返回 **SGL Offset Invalid** 错误

## 与其他传输模型对比

| 传输模型 | 命令/响应传递方式 | 数据传输方式 |
|---------|-----------------|-------------|
| **基于内存** | 显式内存读/写操作 | 显式内存读/写操作 |
| **纯消息** | 胶囊/消息 | 仅通过胶囊/消息 |
| **消息/内存混合** | 胶囊 | 胶囊或显式内存操作 |

三种传输模型适用于不同的应用场景：基于内存适用于本地直连（如 PCIe），而基于消息适用于网络存储场景。^[nvme-transport-models.md:125-133]
