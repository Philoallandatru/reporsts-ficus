# 异步事件通知

异步事件通知（Asynchronous Event Notification, AEN）是 NVMe 规范中的一种机制，允许控制器主动向主机（Host）上报重要事件，而无需主机主动轮询。

## 概述

在控制器初始化流程中，异步事件通知是一个可选但实用的步骤。控制器就绪后，主机可以在任意时刻配置异步事件通知机制，然后提交异步事件请求（Asynchronous Event Request, AER）命令来启用事件监听。^[nvme-controller-initialization.md:10,72]

### 核心概念

| 术语 | 英文 | 说明 |
|------|------|------|
| 异步事件请求 | Asynchronous Event Request (AER) | 主机提交的命令，用于注册对异步事件的监听 |
| 异步事件通知 | Asynchronous Event Notification (AEN) | 控制器主动发送的事件通知 |

## 工作流程

1. **配置阶段**：主机在控制器就绪后配置异步事件机制
2. **提交 AER**：主机提交 AER 命令到管理队列（Admin Queue）
3. **事件监听**：控制器在后台监听需要上报的事件
4. **主动通知**：当特定事件发生时，控制器通过完成队列（Completion Queue）向主机发送异步事件通知

这一流程在 NVMe 控制器初始化概念的流程图中被描述为"启用事件监听 + 提交 AER"。^[nvme-controller-initialization.md:32]

## Discovery 控制器的特殊处理

在 NVMe-oF 架构中，Discovery 控制器对异步事件通知有特殊处理。当客户端请求变更通知（Change Notification）且 Keep Alive Timeout 非零时，控制器会预分配 AER/AEN 资源，确保能够及时向主机推送事件更新。^[nvme-controller-initialization.md:100,114]

具体流程如下：

```
收到 Connect 请求
  |
  |-- 如果请求变更通知 + 非零 KATO
  |      ├─> 控制器可调整 KATO（Keep Alive Timeout）
  |      ├─> 预分配 AER/AEN 资源（异步事件）
  |      ├─> Connect 成功
  |      └─> 主机提交 AER（Asynchronous Event Request）
  |
  └-- 否则
         ├─> 使用固定的 KATO
         └─> 主机完成连接，不提交 AER
```

^[nvme-controller-initialization.md:96-108]

## 配置时机

异步事件通知的灵活之处在于其配置时机。主机可以在控制器就绪后的任意时刻配置异步事件通知，不必与初始化流程同步进行。^[nvme-controller-initialization.md:72]

## 与相关机制的关系

- [[控制器初始化]]：异步事件通知是控制器初始化的可选步骤之一
- 管理队列：AER 命令通过管理队列提交
- 异步事件请求：AER 是主机用于注册事件监听的命令
