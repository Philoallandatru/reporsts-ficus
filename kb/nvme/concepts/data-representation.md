# 数据表示（Data Representation）

NVMe 的很多“读错字段”问题，并非命令不懂，而是把数字、单位或字节顺序看错了。这个页面说明规范如何书写和编码这些基础信息。 [PDF p. 25](../_source/pages/page-025.md)

## 先记住：数字不一定等于数量

若字段明确写着“从零开始编码”（0's based），字段值 `n` 表示的实际数量是 `n + 1`。所以值 `0` 常常表示“一个”，而不是“零个”。未特别说明时，值按从一开始理解。 [PDF p. 25](../_source/pages/page-025.md)

**案例：**队列大小字段若采用从零开始编码，驱动写入 `15` 时请求的是 16 个条目。忘记加一会导致队列容量判断少一个。 [PDF p. 25](../_source/pages/page-025.md)

## 字节顺序：低位字节先放

```text
一个 dword（4 字节）的内存顺序
bit 31                         bit 0
+--------+--------+--------+--------+
| byte 3 | byte 2 | byte 1 | byte 0 |
+--------+--------+--------+--------+
   高位字节                     低位字节
```

图为根据规范 Figure 3 重绘的解释性示意。除非某结构另有说明，多字节数据使用小端序：word 为 2 字节，dword 为 4 字节，qword 为 8 字节。 [PDF p. 27](../_source/pages/page-027.md)

## 数字和单位怎么读

| 写法 | 含义 | 例子 |
|---|---|---|
| `80h` | 十六进制，后缀 `h` | 寄存器或状态码常见 |
| `10b` | 二进制，后缀 `b` | 位字段取值常见 |
| `175` | 十进制，没有后缀 | 普通数量 |
| `1G` | 十进制单位，`10^9` | 容量或速率语境要看字段定义 |
| `1Gi` | 二进制单位，`2^30` | 内存容量语境常见 |

长十六进制数每 8 位可用下划线分隔，长二进制数每 4 位可分隔；这只为可读性，不改变数值。完整单位表覆盖至 `Y = 10^24` 与 `Yi = 2^80`。 [PDF pp. 25-26](../_source/pages/page-025.md)

## 字符串不是任意字节

| 类型 | 可用编码 | 填充方式 |
|---|---|---|
| ASCII 字符串 | `20h` 到 `7Eh` | 左对齐，非空终止时右侧补空格 |
| UTF-8 字符串 | 规范允许的 UTF-8 字节范围 | 左对齐；空终止后的填充用空字节 |

**案例：**读取 Identify 数据中的名称时，先按它声明的字符串规则截取和去除填充；不要把末尾补齐字节误当作名称的一部分。 [PDF pp. 25-28](../_source/pages/page-025.md)

## 容易混淆的地方

- `GB` 与 `GiB` 的基数不同，不能在容量计算中混用。
- “小端序”描述内存中多字节值的排列，不是把二进制文本从右向左读。
- 0's based 只在字段明确这样定义时才适用。 [PDF pp. 25-27](../_source/pages/page-025.md)
