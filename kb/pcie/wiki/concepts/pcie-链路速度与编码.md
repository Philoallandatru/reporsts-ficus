# PCIe 链路速度与编码

PCIe 链路速度与编码是物理层传输效率的核心参数。不同的 PCIe 代际采用不同的信号速率和编码方案，直接影响链路的有效带宽和功耗特性。

---

## 概述

PCIe 链路速度指每秒传输的符号数量（GT/s，即 Gigatransfers per second），而编码方案决定了每个符号能携带多少有效数据位。两者共同决定了链路的**有效带宽**。^[pcie-ltssm.md:189-195]

**核心关系**：

```
有效带宽 = 符号速率 × (有效数据位 / 编码位) × Lane 数量
```

例如，PCIe Gen 3 x16 的有效带宽计算如下：

```
8.0 GT/s × (128/130) × 16 ≈ 15.75 GB/s
```

---

## 各代际速度与编码

PCIe 从 Gen 1 到 Gen 5 共定义了 5 代速度等级，编码方案经历了从 8b/10b 到 128b/130b 的演进。^[pcie-ltssm.md:189-195]

### 速度世代对照表

| 代际 | 符号速率 | 编码方案 | 编码开销 | x1 有效带宽 | x16 有效带宽 |
|------|----------|----------|----------|-------------|--------------|
| Gen 1 | 2.5 GT/s | 8b/10b | 20% | 250 MB/s | 4 GB/s |
| Gen 2 | 5.0 GT/s | 8b/10b | 20% | 500 MB/s | 8 GB/s |
| Gen 3 | 8.0 GT/s | 128b/130b | 1.54% | ~984 MB/s | 15.75 GB/s |
| Gen 4 | 16.0 GT/s | 128b/130b | 1.54% | ~1.97 GB/s | 31.5 GB/s |
| Gen 5 | 32.0 GT/s | 128b/130b | 1.54% | ~3.94 GB/s | 63 GB/s |

### 编码效率提升

从 Gen 2 到 Gen 3，PCIe 将编码从 8b/10b 升级为 128b/130b，编码开销从 **20% 大幅降低到 1.54%**。这意味着：

- Gen 3 的实际带宽几乎是 Gen 2 的两倍（即使符号速率仅从 5 GT/s 提升到 8 GT/s）
- 更少的编码开销降低了功耗
- 128b/130b 编码提供了更好的直流平衡

## 8b/10b 编码

### 原理

8b/10b 编码将每 8 位数据转换为 10 位符号传输。这种编码方式最初由 IBM 在 1983 年提出，被广泛应用于串行总线（如 USB 3.0、SATA、PCIe Gen 1/2）。^[pcie-ltssm.md:189-195]

### 编码特性

| 特性 | 说明 |
|------|------|
| **编码开销** | 20%（每 10 位中有 2 位用于编码） |
| **直流平衡** | 运行 Disparity（RD）保持平衡，确保 0 和 1 的数量大致相等 |
| **特殊符号** | 定义了 12 个特殊控制符号（K 码），用于链路管理和帧定界 |
| **位锁定** | 丰富的比特转换模式便于接收端实现位锁定 |

### 8b/10b 编码表（部分）

8b/10b 编码将 8 位数据分成 3 位和 5 位两组，分别编码：

```
原始数据: Dxx.y
- xx = 5 位值 (0-31)
- y = 3 位值 (0-7)

编码后: 10 位符号
```

**示例**：

| 原始数据 | 编码符号 | 说明 |
|----------|----------|------|
| D0.0 | 1001110100 | 常规数据 |
| D10.2 | 0101110100 | 常规数据 |
| K28.0 | 0011110100 | Comma（comma 用于对齐） |
| K28.5 | 1011110100 | 空闲符号 |

### 在 PCIe Gen 1/2 中的应用

PCIe Gen 1 (2.5 GT/s) 和 Gen 2 (5.0 GT/s) 使用 8b/10b 编码的优势在于：

- **成熟的PHY设计**：多年优化，硬件实现成熟稳定
- **优秀的信号完整性**：高转换密度便于时钟恢复
- **简单的直流平衡**：RD 机制易于实现

## 128b/130b 编码

### 背景

随着信号速率提升到 8 GT/s 及以上，8b/10b 编码的 20% 开销变得难以接受。PCIe Gen 3 引入 128b/130b 编码，将开销降低到约 **1.54%**。^[pcie-ltssm.md:189-195]

### 编码结构

128b/130b 编码在传输数据时附加 2 位的**帧同步头**：

```
┌────────────────────────────────────────┐
│ 2 位同步头 │     128 位有效数据          │
└────────────────────────────────────────┘
```

**同步头模式**：

| 同步头 | 含义 |
|--------|------|
| `01` | 数据块（Data Block） |
| `10` | 有序集（Ordered Set，如训练序列） |
| `00` / `11` | 保留（用于帧同步恢复） |

### 128b/130b 的改进

| 改进项 | 8b/10b | 128b/130b |
|--------|--------|-----------|
| 编码开销 | 20% | 1.54% |
| 控制符号 | 12 个 K 码 | 通过帧头标识 |
| 扰码 | 可选 | 强制使用（128b/130b 块扰码） |
| 直流平衡 | RD 机制 | 加扰（Scrambling） |

### 加扰（Scrambling）

128b/130b 编码强制使用自同步扰码器，使用多项式：

```
G(x) = x^23 + x^21 + x^16 + x^12 + x^8 + x^5 + 1
```

**加扰的作用**：

1. **分散频谱能量**：避免重复数据模式产生集中频谱分量
2. **改善直流平衡**：近似实现直流平衡
3. **降低 EMI**：减少谐波干扰

## 带宽计算详解

### 计算公式

```
有效带宽 (GB/s) = 符号速率 (GT/s) × 编码效率 × Lane 数量 / 8
```

其中编码效率：

- 8b/10b：8/10 = 0.8
- 128b/130b：128/130 ≈ 0.9846

### 计算示例

**PCIe Gen 3 x8 带宽**：

```
8.0 GT/s × (128/130) × 8 / 8 ≈ 7.88 GB/s
```

**PCIe Gen 5 x16 带宽**：

```
32.0 GT/s × (128/130) × 16 / 8 ≈ 62.5 GB/s
```

### 不同 Lane 宽度的带宽

以 Gen 4 (16.0 GT/s, 128b/130b) 为例：

| Lane 数量 | 理论带宽 |
|-----------|----------|
| x1 | ~1.97 GB/s |
| x2 | ~3.94 GB/s |
| x4 | ~7.88 GB/s |
| x8 | ~15.75 GB/s |
| x16 | ~31.5 GB/s |

## 编码对系统设计的影响

### 信号完整性考量

不同编码方案对信号设计有不同的影响：

| 考量因素 | 8b/10b (Gen 1/2) | 128b/130b (Gen 3+) |
|----------|------------------|-------------------|
| 串扰 | 高转换密度有利 | 低转换密度挑战更大 |
| 抖动容限 | 宽松 | 严格（速率更高） |
| 信道损耗 | 允许较高损耗 | 需要更低损耗材料 |
| 均衡需求 | 简单均衡 | 复杂 CTLE + DFE |

### 功耗特性

编码方案影响功耗的多个方面：

1. **编码开销功耗**：8b/10b 的 20% 开销意味着 20% 的额外功耗用于无效数据传输
2. **PHY 设计复杂度**：128b/130b 的高速率需要更复杂的模拟前端
3. **均衡器功耗**：Gen 3+ 需要更耗电的均衡电路

### 成本考量

| 因素 | 影响 |
|------|------|
| PCB 材料 | Gen 4+ 通常需要低损耗材料（如 Megtron 6） |
| 连接器 | 更高频率对连接器要求更高 |
| 布局复杂度 | 更高速度需要更严格的阻抗控制 |

## 速度协商与切换

### 链路训练中的速度协商

在 LTSSM 的 Configuration 和 Recovery 阶段，链路双方交换训练序列（TS1/TS2），协商双方支持的速度。^[pcie-ltssm.md:139-144]

**协商过程**：

```
1. 双方发送 TS1，声明各自支持的速度列表
2. 选取双方都支持且最优的速度
3. 如需切换到更高速度，进入 Recovery.Speed 状态
4. 重新锁定 CDR，进行比特锁定和符号锁定
```

### 速度降级机制

链路可能因信号质量问题降级到较低速度：

```
Gen 5 → Gen 4 → Gen 3 → Gen 2 → Gen 1
```

**降级触发条件**：

- 比特错误率（BER）超过阈值
- 连续多个错误 DLLP/TLP
- Recovery 状态频繁进入

## 实际应用建议

### 带宽需求对照

| 应用场景 | 推荐配置 |
|----------|----------|
| NVMe SSD | Gen 4 x4 (~8 GB/s) 或 Gen 5 x4 (~16 GB/s) |
| 高端 GPU | Gen 4 x16 (~32 GB/s) |
| 10GbE 网卡 | Gen 3 x4 (~8 GB/s) |
| 入门级设备 | Gen 3 x1 (~1 GB/s) |

### 验证链路速度

使用 Linux 命令查看当前链路状态：

```bash
lspci -vvv -s 01:00.0 | grep -i "lnk"
```

输出示例：

```
LnkCap: Port #0, Speed 16GT/s, Width x4, ASPM L0s L1
LnkSta: Speed 16GT/s (ok), Width x4 (ok)
```

### 性能优化

1. **确保 BIOS 中启用了最高速度支持**
2. **使用支持对应速度的插槽**（某些插槽可能限制为 Gen 3）
3. **检查 PCB 走线长度和阻抗**
4. **低损耗线缆**用于外部连接

## 总结

1. **PCIe 共 5 代速度**：从 Gen 1 的 2.5 GT/s 到 Gen 5 的 32.0 GT/s
2. **两种编码方案**：8b/10b（Gen 1/2）与 128b/130b（Gen 3+）
3. **编码开销显著降低**：从 20% 降至 1.54%，大幅提升有效带宽
4. **带宽计算**：有效带宽 = 符号速率 × 编码效率 × Lane 数量 / 8
5. **高速挑战**：Gen 3+ 需要更好的信号完整性设计和更低损耗的材料
