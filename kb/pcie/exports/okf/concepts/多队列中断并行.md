# 多队列中断并行

## 概述

多队列中断并行（Multi-Queue Interrupt Parallelism）是一种通过为每个硬件队列分配独立中断向量，使多个 CPU 核心能够并行处理中断的技术。这种架构消除了单队列模型的串行化瓶颈，显著提升了高性能设备（如 NVMe 存储、网络适配器）的 I/O 性能。^[pcie-msix.md:56-59]

## 工作原理

### 传统单队列模型的局限

在传统单队列架构中，设备只有一个 I/O 队列和单一中断向量，所有 I/O 完成事件都必须经由同一个 CPU 核心处理。这种设计导致 CPU 0 成为性能瓶颈——它需要串行处理所有中断请求，无法利用其他空闲核心的计算能力。^[pcie-msix.md:475-481]

### MSI-X 多队列并行架构

MSI-X 支持多达 2048 个独立配置的中断向量，每个中断具有独立的地址和数据，并可单独启用或禁用。基于内存的配置存储方式使得中断向量可以非连续分配，为多队列设备提供了灵活的映射能力。^[pcie-msix.md:9-14]

多队列并行的工作流程如下：

```
┌────────┐      ┌───────┐
│ Queue 0│─────>│ CPU 0 │
├────────┤      ├───────┤
│ Queue 1│─────>│ CPU 1 │
├────────┤      ├───────┤
│ Queue 2│─────>│ CPU 2 │
├────────┤      ├───────┤
│ Queue 3│─────>│ CPU 3 │
└────────┘      └───────┘
优势: 并行处理，无锁竞争
```

每个硬件队列对应一个独立中断向量，当设备完成 I/O 操作时，触发对应队列的中断并发送到特定 CPU 核心。各核心独立处理各自队列的中断，避免了锁竞争和缓存同步开销。^[pcie-msix.md:482-493]

## 典型应用场景

### NVMe 存储

NVMe 设备为每个 I/O 队列配置独立中断，实现了真正的并行处理。以 4 核 CPU 为例，4 队列配置可达约 1.8M IOPS，是单队列配置（约 500K IOPS）的 3.6 倍。^[pcie-msix.md:56, pcie-msix.md:498-499]

### 多队列网卡

高速网卡为每个 RX/TX 队列独立分配中断向量。在 16 核 CPU 系统上，16 队列配置可达到 80+ Gbps 的吞吐量，实现接近线性的性能扩展。^[pcie-msix.md:57, pcie-msix.md:502-504]

### 其他设备

GPU 的多引擎异步通知和存储控制器的多通道并行处理同样受益于多队列中断并行架构。^[pcie-msix.md:58-59]

## CPU 亲和性配置

### 中断绑定策略

通过设置中断亲和性（Interrupt Affinity），可以将每个队列的中断绑定到特定 CPU 核心。这种绑定确保了中断处理与特定核心的本地缓存数据保持一致，减少跨 NUMA 节点的内存访问延迟。^[pcie-msix.md:506-518]

典型配置代码如下：

```c
for (i = 0; i < num_queues; i++) {
    int cpu = i % num_online_cpus();
    irq_set_affinity_hint(queue[i].irq, cpumask_of(cpu));
}
```

该策略将队列 N 绑定到 CPU N，实现循环分配。^[pcie-msix.md:514-517]

### NUMA 优化

在 NUMA（非统一内存访问）系统中，应将队列绑定到访问本地内存延迟最低的 CPU 核心。例如，NUMA Node 0 上的 CPU 0-7 应处理本地 NVMe 队列 0-7，NUMA Node 1 上的 CPU 8-15 应处理本地队列 8-15，从而实现最优的内存访问延迟。^[pcie-msix.md:520-529]

## MSI-X 中断发送流程

设备发送多队列中断的完整流程如下：

1. **事件检测**：设备检测到特定队列的 I/O 完成事件
2. **向量确定**：根据队列编号确定对应的中断向量号（如队列 3 → 向量 3）
3. **配置读取**：从 MSI-X Table 中读取该向量的 Message Address 和 Message Data
4. **屏蔽检查**：检查 Vector Control 位的 Mask Bit 状态
5. **消息发送**：若未屏蔽，构造 Memory Write TLP 并发送到目标地址

Root Complex 接收 TLP 后，识别 MSI 地址范围，提取目标 CPU（从 Address[19:12]）和中断向量（从 Data[7:0]），然后触发相应 CPU 核心的中断处理程序。^[pcie-msix.md:391-418]

## 性能优势

多队列中断并行的核心优势包括：

| 维度 | 单队列 | 多队列并行 |
|------|--------|------------|
| CPU 利用率 | 仅单核处理 | 多核并行 |
| 锁竞争 | 严重 | 无 |
| 缓存效率 | 低（跨核心访问） | 高（本地缓存命中） |
| 扩展性 | 受限 | 线性扩展 |

^[pcie-msix.md:493,504]

## 配置工具

### 查看中断统计

通过 `/proc/interrupts` 可以观察各队列中断的负载分布：

```bash
cat /proc/interrupts | grep nvme
  130:  123456  0      0      0      IR-PCI-MSI 524288-edge nvme0q0
  131:  0       234567 0      0      IR-PCI-MSI 524289-edge nvme0q1
  132:  0       0      345678 0      IR-PCI-MSI 524290-edge nvme0q2
  133:  0       0      0      456789 IR-PCI-MSI 524291-edge nvme0q3
```

输出显示每个中断向量在不同 CPU 核心上的触发次数，便于评估负载均衡效果。^[pcie-msix.md:571-579]

### 实时监控

使用 `watch` 命令可以实时观察负载均衡状态的变化：

```bash
watch -n1 'cat /proc/interrupts | grep nvme'
```

^[pcie-msix.md:578-579]

## 设计建议

- **高性能设备优先使用 MSI-X**，以获得最多 2048 个独立中断向量
- **中断数量应与队列数量匹配**，通常采用 1:1 的映射关系
- **合理设置中断亲和性**，充分利用多核并行处理能力
- **在 NUMA 系统中优化绑定策略**，减少跨节点内存访问延迟

^[pcie-msix.md:623-627]
