# 单账户持仓以当日截图为准

**只有一个证券账户时，用户发来的持仓截图当天就是最终持仓；把它按日期存成一份快照，所有下游（日报、盘中监控、看板）只读这一份。**

## 背景

finance 工作区里同时存在两类持仓数据：券商 App 持仓截图，和小A看板工作流里的逐笔成交流水（可重放出持仓）。早先的设计把它们当成「两个账户、互不覆盖」，结果同一账户的持仓在日报和盘中简报里各说各话。

真正的关系是：**流水是推导材料，截图是事实**。流水只到 11-13，截图到 11-17；流水重放出来的持仓和 App 显示的对不上时，App 是准的。

## 核心内容

### 归档规则

- 截图按**用户发送当天（北京时间）**记为该日最终记录，落盘 `.private/holdings/YYYY-MM-DD.json`。
- 同一天收到多张截图，以最后一张为准。
- 截图里正数量的标的 = 完整在持仓清单；零数量和未列出的旧标的退出持仓。
- 盘中监控在当天还没有新快照时，可以沿用最近一份，但必须标注日期并写明是历史参考。

### 来源优先级

```text
                  目标日 T
                     |
        +------------+------------+
        |                         |
  有 T 的持仓快照？            没有快照
        |                         |
   快照优先（事实）        workflow 成交是否覆盖 T？
                                  |            |
                               覆盖          不覆盖
                                  |            |
                        完整持仓导出可直接用   两者都缺
                        成交流水须够重放持仓      |
                                  |      当日持仓标「数据不足」
                                  +-----> 不得用上一日余额充数
```

优先级不是随意的：**较旧的导出不能覆盖较新的截图**，同样，上一日的持仓余额不能当成当天已确认的最终持仓。

### 三个消费端共用一份快照

```text
                    .private/holdings/2026-11-17.json
                    （当日最终持仓：数量/成本/市值/资金）
                                |
        +-----------------------+-----------------------+
        |                       |                       |
   持仓日报                 盘中飞书简报            小A看板
 holdings_daily.py       intraday_push.py        我的持仓 / 收盘持仓
        |                       |                       |
 reports/YYYY-MM-DD_     15 分钟纪律判定         /api/workflow/recap
 持仓每日分析.md                              /positions?date=
 holdings/out/*.json
```

好处是「只有一处需要更新」：换仓、改成本、标清仓都只动一个文件，三边自动一致，不会出现日报说 3 只、简报说 5 只的情况。

### 必须区分「确认空仓」与「资料不足」

当天确实一笔不剩，是**确认空仓**；当天没有任何资料，是**资料不足**。两者都渲染成空列表的话，人会以为已经清仓而不再管它。接口用一个 `available` 标志区分，界面上分别显示「这一天收盘时没有净持仓」和「当日持仓数据不足」。

## 症状与根因

> 现象：日报里的持仓和 App 截图对不上，盘中简报又是另一套。

根因不是取数错，而是**同一账户有两份互不知情的持仓来源**。修复方式不是让两边对齐，而是消灭重复来源：一张截图 → 一份按日期的快照 → 所有消费端只读它。

## 关键要点

- 截图当天即最终持仓，日期取用户发送时刻（北京时间），不是取截图里的行情日期。
- 快照要能独立对账：各行市值之和 = 总市值，各行当日盈亏之和 = 当日参考盈亏，浮亏之和 = 浮动盈亏。
- 逐笔成交的日期、成交价、时刻、费用**不能从截图反推**——截图只有数量和盈亏。缺项留空或标注未提供。
- 流水覆盖不到当天时，日报要显式写明逐笔成交的最后日期（如「最后成交日 2026-11-13」），不要让人以为持仓算到了当天。
- 规则要写进 `AGENTS.md` 这类常驻指令，否则下次 Agent 又会按旧习惯另开一份账户。
