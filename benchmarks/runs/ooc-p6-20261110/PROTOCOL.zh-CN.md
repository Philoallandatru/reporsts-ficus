# P6 尺寸分组缓存：预先固定的方法

2026-11-10。保持当前分支和 P0-P5 未提交修改，只改变专家 RAM 缓存布局。以 `D:/llama-ooc-p5-20261110/p5-source` 为阶段源码基点、`file-bin` 为旧二进制；P6 产物单独保存，不覆盖 P5。

精确尺寸分组，按已注册专家数量平衡各组覆盖比例。每次给仍可容纳一个完整单元且覆盖比例最低的组增加一槽；相同比例时尺寸较小的组优先。预算包括全部组描述符、entry 和实际 payload；每组独立 LRU。分配在 session 创建时固定，运行中不跨组借用。该策略没有根据正式提示调参，不能保证适合所有偏斜热点；报告实际命中和残余浪费。PLE 的 `cache_ways=4` 继续旧固定槽和组相联路径。prefill admission、读取合并、RAM/GPU 互斥驻留均不改变。

主要性能指标为 Q5 decode token/s，目标中位数改善至少 10%，且关键指标无显著退化。复用 P5 的正式提示、固定 teacher-forcing token 轨迹、GPU 4096 MiB、RAM 16384 MiB、staging 32 MiB、depth 2、PLE 64 MiB、实际相同 microbatch、完整 top-10、Q8 KV、单 5080。六组 P5/P6 AB/BA 交替，每组均保留全部样本，禁止只挑最快轮。IQ2 同样六组配对，用于不同尺寸分布的回归。计时组关闭运行期 GPU 查询，保留启动前 GPU 预检和 0.5 秒主机监控；长测保留 GPU 采样。保持 P5 新进程、热 OS 缓存、禁用 Q5 加载预取及 48 GiB 测试进程工作集上限条件。

分别报告完整请求墙钟、加载/端到端首 token、prefill/decode、token p50/p95/p99。读盘采用 P5 检查点差值：排除 prefill 和各请求前 32 个输出，按实际 decode 调用数计算逻辑与对齐 MiB/token。报告 RAM payload/allocated、命中、淘汰、RAM/GPU 重复驻留。direct 完成字节不冒充物理 I/O；长测使用逐事件 ETW DiskIO 交叉核对。

正确性要求同 GPU 路径 logits 逐位相同。六轮全部对比旧路径；固定评测文本 PPL、512 实际 context 边界及清 KV 复用分别测试。长测使用 P5 完整已固定轨迹：8192-token 提示 +512 输出、多主题共 7680 输出、持续至少 30 分钟；使用 RAM 8192 MiB 和上述其余预算，和保存的 P5 原生 GPU 参考逐位比较。长期资源保护维持 available RAM、commit 余量各 4 GiB、D 盘余量 12 GiB。仅终止自己的试验，不清全局页缓存、不改 pagefile、不停止其他任务。大量模型哈希在性能与长测结束后进行。

单元和 backend 验证覆盖零预算、不能容纳单元、真实混合尺寸、组内压力、跨组互不污染、超大单元 bypass、事件租约、取消与失败排空、重试和 PLE。记录最初测试失败和修正，不删除证据。第一轮失败是新增测试请求了已缓存的大单元，未触发预期的 I/O 取消钩子；将测试预算从 3 MiB 改成 2 MiB 以强制大单元淘汰后，通过全部测试。

P5 原有 CPU fallback 数值失败和 IQ2 带监测短测失败仍保留；本轮不扩大其通过范围。没有达到 10% 就报告 P6 性能目标未达成，不更换阈值。
