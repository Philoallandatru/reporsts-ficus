# P6：按专家尺寸分组的 RAM 缓存

2026-11-10。当前分支 `feature/file-expert-store-p0-p2`；保留此前未提交改动，未提交或推送。

Q5 六组交替配对的 decode 吞吐中位数由 **2.242 增至 2.449 token/s（+9.26%）**，预先固定的 10% 门槛未通过。稳态逻辑读取从每次实际 decode 464.11 MiB 降至 385.39 MiB。完整正确性、预算及长时验证见下文；性能结论仅针对这组模型、轨迹和配置。

## 实现与范围

P5 所有 RAM 槽按最大专家角色大小分配；P6 按精确字节大小建立固定分组，每组独立 LRU。启动时反复给可容纳完整单元且 `slots / registered_units` 最低的组增加一槽，比例相同则较小尺寸先分配。各组覆盖比例接近，不按组数均分预算。组描述符、entry、payload 共同计入 RAM 硬预算；没有把随容量增长的索引放到统计之外。

Q5 的 73728 个专家角色单元分为 1126400 B（48128 个）、1344000 B（1024 个）、1740800 B（24576 个）三组。16 GiB 预算下分配 8404/179/4292 槽，共 12875 槽；旧布局为 9868 槽。三组描述符共 120 B，entry 仍为每槽 40 B；实际总分配 17178870320 B，低于 17179869184 B。PLE 保持原四路组相联、相同槽数和独立预算，session 固定控制对象仅增加 16 B。

没有改变 prefill admission、读取合并、RAM/GPU 重复驻留、GPU 缓存、top-k、dtype、执行内核或微批策略。租约、部分填充、事件等待与失败排空沿用原实现。尺寸组启动后不互借容量，冷组仍可能浪费预算；这不是动态热点自适应分配器。

## 对照方法

P5 原始 `file-bin` 与冻结的 P6 候选在当前环境六组 AB/BA 交替重测，保留每轮。两套包只有 `llama.dll` 不同，probe 与 ggml DLL 哈希一致。正式输入和 teacher-forcing 轨迹复用 P5。单 RTX 5080、GPU 专家 4096 MiB、RAM 专家 16384 MiB、staging 32 MiB、depth 2、PLE 64 MiB、32K context、完整 top-10、Q8 KV、CPU miss share=0；实际 microbatch 从运行记录核对。

新进程、热 OS 缓存，不清缓存。Q5 关闭加载预取并保持 48 GiB 测试进程工作集上限。短计时组关闭运行期 GPU 查询、保留启动前预检和每 0.5 秒主机采样；长测保留 GPU 采样。所有组使用同样资源保护。逻辑/对齐读取统计排除 prefill 和每请求前 32 个输出，分母是实际 decode 调用。完整条件见 [预定协议](PROTOCOL.zh-CN.md)。

Q5 的逻辑读取下降约 16.96%、RAM 请求命中提高约 8.02 个百分点，但 H2D payload 仍约 983.3 MiB/decode；读取减少不等于全部端到端成本同比减少。请求墙钟中位数缩短约 5.22%，prefill 吞吐约 -0.69%，TTFT 约 +0.69%，后两项配对区间跨过无变化；decode p50/p95/p99 均下降。六轮正式配对内没有观察到关键指标显著退化，但主要性能门槛仍未通过。

IQ2 的短轨迹在两版均未触发 RAM 淘汰，逻辑读取和命中计数相同。其约 1.07% 吞吐差的配对区间包含无变化，不能宣称已证明该分布提速。末尾有效载荷只占约 78.6%，因为本轨迹尚未填满缓存，不能把剩余空间全算作槽内碎片。

缓存填满后的有效载荷增加会占用更多实际工作集；相同缓存预算不意味着 RSS 完全相同。entry、组元数据与各级缓存计费均通过；进程整体 RAM/commit 还包括固定权重、图、KV、驱动等。短计时组没有运行期 VRAM 峰值，不能用启动前显存检查冒充峰值；长测另提供显存采样。

31 次运行的 GPU 专家分配最大 4094.48 MiB，低于 4096 MiB 预算；实际 CUDA 图 compute 分配最大 1,871,090,816 B（1784.41 MiB），低于独立的 4096 MiB 图预算。所有运行实际 microbatch 均为 512。GPU 专家预算不包含固定权重、KV 与图分配，不能当作整卡显存上限。

Q5 末检查点 RAM/GPU 重复角色字节的六轮值：P5 `[3599385600, 3599385600, 3599385600, 3599385600, 3599385600, 3599385600]`，P6 `[3687244800, 3687244800, 3687244800, 3687244800, 3687244800, 3687244800]`。重复驻留仍存在，没有将其从两侧预算扣除。P5/P6 六轮专家淘汰数分别为 `[43824.0, 43824.0, 43824.0, 43824.0, 43824.0, 43824.0]` / `[32995.0, 32995.0, 32995.0, 32995.0, 32995.0, 32995.0]`。完整统计见 [performance.json](performance.json) 与 [analysis.json](analysis.json)。

## 正确性、长时与物理 I/O

全部六对 Q5、六对 IQ2、固定文本 PPL、context 边界、RAM=0、同步控制都通过；最终比较器直接核对 float32 的 uint32 位模式，包含 signed zero。配对的 GPU 路由 trace 字节完全相同。长测与 P5 保存的原生 GPU 参考对比 **1,907,097,600 个 logits 逐位相同**。这份历史参考用于数值验证，未用历史耗时宣称本轮提速。

固定评测文本的 PPL（P5 / P6）：science，92 个位置，6.183250 / 6.183250；software，83 个位置，17.357956 / 17.357956。同一文本亦与保存的原生参考相同。

P6 长测使用 RAM 8 GiB、GPU 4 GiB，完成实际 8192-token 提示、首请求 512 输出、15 个跨主题请求合计 7680 输出。推理持续 130.72 分钟，进程墙钟 130.75 分钟；完成首 4096 输出后继续推理 70.18 分钟，也满足原计划要求的后续至少 30 分钟。本轮预先固定完整 15 请求轨迹，未按速度动态增加请求；总时长与后续时长分别核对。清 KV 保留权重缓存，持续淘汰，退出时 expert/PLE in-flight 与 leases 为零。

首个请求的输出 448-512 出现暂时性慢段：两个 32-token 窗口分别约 111/106 秒，读完成等待约 98/93 秒，随后同一进程自行恢复。后续请求也有间歇慢读，所有慢段和时延均保留。现有采样可定位到读完成等待占主导，不能证明 SSD、驱动或监控工具是根因；详见 [诊断记录](DIAGNOSIS.md)。长测没有当前环境的配对 P5 耗时，因此不将历史耗时差当作 P6 的因果性能结论。

为完整呈现耗时，历史 P5 文件路径同轨迹的推理/进程墙钟为 74.71/74.74 分钟，本次为 130.72/130.75 分钟。本次长测耗时更长，六组短测收益不能推广为长时吞吐收益；历史与当前长测没有交替配对，不能据此分离缓存改动与运行环境的影响。

相同长轨迹和预算的确定性检查点则可对照读取工作量：P5/P6 分别为 664.084/596.881 逻辑 MiB/decode（-10.12%），对应 7185 次排除预热后的实际 decode；此处比较计数，不比较配对耗时。

该次长测的 decode 吞吐为 1.082 token/s，逐 token p50/p95/p99 为 453.34 / 1154.39 / 13528.18 ms；首个 8K 请求 TTFT 为 559.90 秒。这些是包含慢段的描述性数据，不是与当前 P5 配对的提速结论。

全程 7665 次 decode 中，422 次超过 1 秒，314 次超过 5 秒，最长单次 29.07 秒。最慢检查点窗口在请求 15 的输出 480–512：31 次 decode 共 240.54 秒，其中读取等待 219.25 秒、上传等待 7.30 秒。全部窗口见 [long-slow-summary.json](long-slow-summary.json)。

长测 RSS/private 峰值 13.465/21.441 GiB；可用 RAM/commit 最低余量 42.818/13.907 GiB；受测整卡显存峰值 12514.0 MiB（含其他进程及驱动）。

全系统文件缓存采样峰值 47.609 GiB，不能归给单个模型进程。PSAPI 共 27 次工作集快照，枚举到的 private resident 峰值 8.862 GiB，Locked 标志合计峰值 0 B；该枚举不覆盖工作集外页面和设备/驱动锁页，不能据此宣称 CUDA pinned memory 为零。启动、context、每次 prefill/decode 与关闭的分段数据保存在 analysis.json。

末 15 分钟 private 在 21.411263–21.412403 GiB，线性斜率 -0.030452 MiB/min。采样最大间隔 0.55 秒；GPU 查询错误 0 次。采样不代表未采到的瞬时峰值。

排除 prefill 和各请求前 32 个输出后，长测共计 7185 次实际 decode：逻辑/对齐读取 596.881/598.710 MiB/decode，RAM 请求命中 30.732%。路由 trace 保持 top-10，覆盖 23251 个层内专家，合计 86.682 GiB；该集合含小批 prefill，不包含一般路径的提示扫描。末尾专家淘汰数 3,730,883。

稳态 ETW 捕获持续 182.04 秒，但 1 GiB 循环日志导出的 DiskIO 事件只分布在捕获后 107.774–182.028 秒，跨度 74.25 秒。保留记录中按发起 PID 与专家分片归属的专家读取为 18.692 GiB；丢事件/缓冲计数 0/0，目标进程 pagefile hard-fault 字节 0。零丢失计数不排除循环日志覆盖早期记录，不能将这些字节当作完整 182 秒流量，也不能证明未保留时段没有 pagefile 缺页。保留片段仍直接证明完成 4096 输出后存在专家物理读取。

ETW 按逐事件 IO Size 汇总，避开 xperf 大字节汇总回绕；这代表主机块设备接口读取，不是 NAND 内部流量。整盘噪声和其他进程读写保存在原始结果，未归到模型。

另行保留的早期诊断捕获长 121.16 秒，磁盘事件时间跨度 121.14 秒，专家读取 158.455 GiB，丢事件/缓冲 0/0，保留记录中目标进程 pagefile hard-fault 字节 0。它不替代预定的稳态窗口，也不代表首个慢段恰好发生在该捕获范围内。

全系统 Pages Output/sec 的采样积分约 15,752 页。这是系统范围估算，不能归因到受测进程；结合上述 ETW 保留范围，本轮不宣称整个系统或长测全过程完全没有换页。

实际 context=512 的测试成功写入最后位置 511，位置 512 返回预期无槽状态 1；清 KV 后重复结果逐位一致。相关 CTest 2/2 通过。新增测试首次失败属于取消钩子未被缓存命中触发的夹具问题，修正为强制淘汰预算后通过，原日志保留。

结论只适用于受测单 CUDA 卡和相同 GPU 算法路径。P5 的 CPU fallback 数值失败、IQ2 原带运行期 GPU 查询的短测失败及其独立配对复核仍按原报告保留。未证明其他尺寸分布、热点偏斜、模型、多卡、多 context 或 CPU fallback 同样受益；静态组间借用、prefill admission、合并读取和 RAM/GPU 互斥驻留仍是后续单独消融候选。
