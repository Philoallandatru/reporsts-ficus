# Q5 同工作量三方对照

目的：分开量化原生 llama.cpp、P6 文件路径和 Strata 的速度、内存与读盘成本，并用实测决定下一项优化。只使用已有的单张 RTX 5080 和六片 Qwen3.8-Flash-Next UD-Q5_K_XL。两份历史清单的六个 SHA-256 一致；复跑前只检查当前文件大小和时间戳，避免用全文件哈希预热缓存。

- 统一请求：从冻结的 P6 `q5-p6-r1` 取 **128 个提示 token + 128 个强制输出 token**。三个引擎收到相同 token IDs，不经过服务器、聊天模板或网络。保留 P6 原轨迹中的 EOG，禁用提前停止，仅作为固定工作量性能测试。Strata 使用发布版 `STRATA_FOLLOW`，不加载 MTP 文件，禁用后缀和 lookup 草稿，`STRATA_ROUTE_TAIL_SKIP=0`。确认 0 个草稿、0 个 prompt 复用，逐条核对输出 IDs。相同 token 不意味着两种实现的 logits、路由或计算内核逐位相同。
- 相同的专家 GPU 缓存预算 **4 GiB**。Strata 用按旧 Q5 槽尺寸换算的固定槽数，实际大小由启动日志验证；不使用 `auto` 拿更多显存。P6 与 Strata 各用 **16 GiB** 专家 RAM 预算；原生 `mmap` 没有同义的专家 RAM 配额。三个子进程均设置 Windows **24 GiB 硬工作集上限**，保留 OS 文件缓存，其页缓存和私有提交并不等价于专家 RAM 池。记录进程工作集、私有提交、整卡显存峰值、系统 RAM/commit 最小余量。整卡显存受其他占用影响，4 GiB 是专家部分而非全进程显存。
- llama.cpp 两臂使用同一个轻量 probe，不写全量 logits，使用冻结的 DLL；32K context、ubatch 512、单序列、16 线程、Q8_0 KV、GPU MoE CPU share=0。Strata 32K context、INT8 KV、prefill 上限 512、15 expert workers+host，同样限制在 16 个逻辑核上，保留其正常 CPU/GPU 专家分工。不同的内核和 prefill 分块属于引擎差异。
- 先尝试未经修改的 b12211，若加载触发预定资源保护，保留失败，以仅关闭 mmap 加载预取的已归档 b12211 作为原生参考。P6 用 32 MiB staging、depth 2、64 MiB PLE RAM。流程每次重新启动，只跑一条请求，不清理系统缓存，不停止其他任务，不更改页文件或设备设置。只有一个模型工作负载。保留启动/退出、失败和全部计时样本。
- 共同计时：写入请求到第一个可见 token 为 TTFT；第 1 到第 128 个可见 token 之间的 127 个间隔为 decode。由同一个本机 pipe 读取器取时间。观察启动前和运行期进程/整卡资源；同样的 ETW 标志会影响绝对速度，不与旧无 trace 结果直接拼接。
- 物理读：xperf 顺序文件记录 DiskIO 完成事件。确认完整覆盖请求且丢事件、丢缓冲为 0 后，逐事件以整数汇总 PhysicalDrive2 上六片 Q5 的读字节（并单列专家分片 4/5/6）；按文件归属，另保留发起 PID 和整盘计数，避免遗漏 mmap 缺页。主表用首末 token 窗口的 MiB/127，不把逻辑字节或整盘流量当作同口径模型物理读。prefill 读取另列；加载阶段只保留整盘/资源采样，未做分片 ETW。样本窗口边界是 pipe 到达时间，存在小量相位误差。
- 首轮顺序为原生参考、P6、Strata；取得可用结果后轮换顺序，复核中位数和范围。失败保留，不换掉慢样本。实测在共享机器的自然 OS 缓存状态；不声称严格冷启动或所有可能的预算都相等。

预算校准：Strata `--expert-cache 1070` 实际为 1,185 槽、4.41 GiB，排除于正式对照。改为参数 963 后，日志实际为 1,067 槽、3.97 GiB，低于共同 4 GiB 上限，与 llama.cpp 的 4,091.94 MiB 相差不到 1%。预算校准样本单列。原生默认预取样本在加载阶段触发系统 commit 余量保护，余量采样最低 3.29 GiB，正式原生参考使用归档的禁预取版本。
